# 設計書

## 1. 目的

高齢者の転倒を、**映像を外部に出さずに**マイコン内部だけで検知し、すぐに知らせる。

- **プライバシー**: 映像はデバイスの外に出さない。LCD にも生映像ではなく「状態」と「検出枠」だけを表示する
- **即応性**: μT-Kernel の優先度ベースのスケジューリングで、転倒確定から通知までの遅延を小さく、ばらつきなく保つ
- **スタンドアロン**: ネットワークに依存せず、キット同梱品だけで動く

## 2. ハードウェア構成

| 要素 | 使用するもの |
|---|---|
| MCU | RA8P1（R7KA8P1KFLCAC）の Cortex-M85（1GHz）。Cortex-M33 は将来拡張 |
| NPU | Arm Ethos-U55（FSP `rm_ethosu`） |
| カメラ | OV5640、MIPI CSI-2 → VIN（640×480 RGB565、トリプルバッファ）。I2C（ch1, 400kHz）で初期化、XCLK 24MHz は GPT ch12（P501） |
| 表示 | 7 インチ 1024×600、GLCDC（パラレル RGB888 出力）＋ D/AVE 2D |
| メモリ | フレームバッファ・VIN バッファは SDRAM、AI モデルは内蔵フラッシュ（OSPI 不使用） |

## 3. 現在の実装（提出時点）：2 タスク＋互換レイヤー

ルネサス公式の FreeRTOS 版サンプル（2 スレッド構成）を、**ロジックを書き換えずに**μT-Kernel 上で動かすため、FreeRTOS API を μT-Kernel API に置き換える互換レイヤー `src/rtos_to_mtk.h` を作成しました。

| タスク | 優先度 | スタック | 役割 |
|---|---|---|---|
| camera（`camera_display_thread_entry`） | 9 | 8KB | ハード初期化（LCD・カメラ）、フレーム取得、RGB565→INT8 前処理、D キャッシュのクリーン、表示 |
| AI（`ai_inference_thread_entry`） | 10 | 32KB | Ethos-U55 の初期化、YOLO-fastest 推論、後処理（検出枠） |
| task 1〜3 | 10 | 1KB | LED 点滅・シリアル出力（μT-Kernel 動作確認用） |

### 互換レイヤーの対応

| FreeRTOS | μT-Kernel | 補足 |
|---|---|---|
| `xEventGroupWaitBits(ev, bits, clear, all, t)` | `tk_wai_flg(ev, bits, TWF_ANDW/TWF_ORW \| TWF_BITCLR, &ptn, t)` | `TWF_BITCLR` で「待ったビットだけクリア」を再現 |
| `xEventGroupSetBits` | `tk_set_flg` | |
| `xEventGroupClearBits` | `tk_clr_flg(ev, ~bits)` | `tk_clr_flg` は AND パターンなので反転して渡す |
| `xEventGroupGetBits` | `tk_ref_flg` | |
| `xEventGroupSetBitsFromISR` | `tk_set_flg`（タスク独立部として呼び出し） | FSP のコールバック（割り込みコンテキスト）から呼ぶため、BSP2 の HAL ドライバと同様にタスク独立部であることをカーネルに知らせる |
| `vTaskDelay(ticks)` | `tk_dly_tsk(ms)` | 1 tick = 1ms |
| `portMAX_DELAY` | `TMO_FEVR` | |

イベントフラグは `usermain()` で `TA_WMUL`（複数タスク待ち可）属性で 1 つ生成し、両タスクで共有します。

### FSP 割り込みとカーネルの共存

- mtk3_bsp2 は FSP のベクタテーブルを RAM にコピーして使うため、FSP の割り込みハンドラ・コールバックはそのまま動作する（`tk_def_int()` は使わない）
- 割り込み優先度 0 はカーネル管理外のため使わない。カメラ・LCD・NPU の割り込みは優先度 12、D/AVE 2D は 2

## 4. 計画している最終構成：6 タスク

| タスク | 優先度 | 役割 | 同期 |
|---|---|---|---|
| アラート | 5（最高） | 転倒確定で即座に LED 点灯・画面切替・ログ出力 | イベントフラグ待ち |
| システム監視 | 8 | 各タスクの生存確認（周期ハンドラ）、スタック残量の監視 | 周期ハンドラ |
| カメラ取得 | 10 | VIN のフレーム完了割り込みを受けてバッファ切替・前処理 | 割り込み → イベントフラグ |
| 転倒判定 | 11 | 検出枠の時系列から転倒を判定 | メッセージバッファ受信 |
| AI 推論 | 12 | Ethos-U55 推論 → 検出枠を判定タスクへ | メッセージバッファ送信 |
| UI 描画 | 14 | 状態（安全／見守り中／転倒）と抽象化した検出枠を描画（生映像は描かない） | 周期起床 |

「NPU が人を見つけ、μT-Kernel のタスクが時系列で判定・通知する」という役割分担にし、転倒確定後の通知（アラートタスク）を最高優先度に置くことで、描画や推論の負荷に左右されずに通知できるようにします。

## 5. 転倒判定アルゴリズム（計画）

姿勢推定モデルは変換・後処理のリスクが高いため、**物体検出の検出枠（BBox）＋時系列ルール**で判定します。

```
            横長に変化 (h/w < 0.8)
  NORMAL ─────────────────────────▶ SUSPICIOUS
    ▲  ◀──── 縦長に戻る (h/w ≥ 1.2) ────┘ │
    │                                    │ 横長が 3 秒以上継続
    │                                    ▼
    └────── 起き上がる (h/w ≥ 1.2) ──── FALLEN ──▶ アラート発報
```

- 画面内で最も大きい検出枠を対象にする
- 枠の縦横比（h/w）が「縦長 → 横長」に変化し、枠の中心が短時間で大きく下降したら「疑い」
- 横長の状態が一定時間（初期値 3 秒）続いたら「転倒確定」（しゃがむ・座るなどの誤報対策）
- しきい値（0.8 / 1.2 / 3 秒）は実機評価で調整する

## 6. 評価計画

| 評価 | 方法 |
|---|---|
| 検知率・誤報率 | 立つ・歩く・しゃがむ・転倒・起き上がるを各 10〜20 回。転倒動画をタブレットで再生してカメラで撮る方法で安全・再現性を確保 |
| 処理遅延 | `tk_get_otm` で「フレーム取得 → 前処理 → 推論 → 判定 → LED 点灯」の各区間を計測 |
| NPU の効果 | Ethos-U55 使用時と CPU のみの推論時間を比較 |

参考値（公式サンプルを FreeRTOS で実機動作させたときの実測）: カメラ約 30fps、LCD 更新 約 35 回/秒、AI 推論 約 20 回/秒。

## 7. 計画書からの変更点

| 項目 | 計画書（2026/2） | 本作品 | 理由 |
|---|---|---|---|
| ボード | STM32N6570-DK | EK-RA8P1 | 貸与ボードが EK-RA8P1 となったため |
| NPU | Neural-ART（STM32N6） | Arm Ethos-U55 | 同上 |
| AI ツール | STM32Cube.AI | RUHMI Framework | 同上 |
| 検出モデル | 転倒状態の分類 | 物体検出＋時系列ルール | 短期間で確実に動かすため、実績のある検出モデルを採用 |
| 通知 | LED またはネットワーク | LED・LCD・シリアル | キット同梱品のみで審査員が再現できるようにするため |
