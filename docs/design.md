# 設計書

## 1. 目的

高齢者の転倒を、**映像を外部に出さずに**マイコン内部だけで検知し、すぐに知らせる。

- **プライバシー**: 映像はデバイスの外に出さない。LCD にも生映像ではなく「状態」と「検出枠」だけを表示する
- **即応性**: μT-Kernel の優先度ベースのスケジューリングで、転倒確定から通知までの遅延を小さく、ばらつきなく保つ
- **スタンドアロン**: ネットワークに依存せず、キット同梱品だけで動く

## 2. ハードウェア構成

| 要素 | 使用するもの |
|---|---|
| MCU | RA8P1（R7KA8P1KFLCAC）の Cortex-M85（1GHz）。Cortex-M33 は将来拡張 |
| NPU | Arm Ethos-U55（FSP `rm_ethosu`） |
| カメラ | OV5640、MIPI CSI-2 → VIN（640×480 RGB565、トリプルバッファ）。I2C（ch1, 400kHz）で初期化、XCLK 24MHz は GPT ch12（P501） |
| 表示 | 7 インチ 1024×600、GLCDC（パラレル RGB888 出力）＋ D/AVE 2D |
| メモリ | フレームバッファ・VIN バッファは SDRAM、AI モデルは内蔵フラッシュ（OSPI 不使用） |

## 3. ルネサス AI サンプルの移植：互換レイヤー

ルネサス公式の FreeRTOS 版サンプル（カメラ／AI の 2 スレッド構成）を、**ロジックを書き換えずに**μT-Kernel 上で動かすため、FreeRTOS API を μT-Kernel API に置き換える互換レイヤー `src/rtos_to_mtk.h` を作成しました。2 つのスレッドは μT-Kernel のタスク（camera／ai）としてそのまま動作し、アプリケーションとはフック関数（`src/app_hooks.h`）だけでつながっています。

### 互換レイヤーの対応

| FreeRTOS | μT-Kernel | 補足 |
|---|---|---|
| `xEventGroupWaitBits(ev, bits, clear, all, t)` | `tk_wai_flg(ev, bits, TWF_ANDW/TWF_ORW \| TWF_BITCLR, &ptn, t)` | `TWF_BITCLR` で「待ったビットだけクリア」を再現 |
| `xEventGroupSetBits` | `tk_set_flg` | |
| `xEventGroupClearBits` | `tk_clr_flg(ev, ~bits)` | `tk_clr_flg` は AND パターンなので反転して渡す |
| `xEventGroupGetBits` | `tk_ref_flg` | |
| `xEventGroupSetBitsFromISR` | `tk_set_flg`（タスク独立部として呼び出し） | FSP のコールバック（割り込みコンテキスト）から呼ぶため、BSP2 の HAL ドライバと同様にタスク独立部であることをカーネルに知らせる |
| `vTaskDelay(ticks)` | `tk_dly_tsk(ms)` | 1 tick = 1ms |
| `portMAX_DELAY` | `TMO_FEVR` | |

サンプル用のイベントフラグ `g_ai_app_event` は `usermain()` で `TA_WMUL`（複数タスク待ち可）属性で生成し、camera・ai・ui タスクで共有します。

### FSP 割り込みとカーネルの共存

- mtk3_bsp2 は FSP のベクタテーブルを RAM にコピーして使うため、FSP の割り込みハンドラ・コールバックはそのまま動作する（`tk_def_int()` は使わない）
- 割り込み優先度 0 はカーネル管理外のため使わない。カメラ・LCD・NPU の割り込みは優先度 12、D/AVE 2D は 2

## 4. タスク構成：6 タスク（実装済み）

| タスク | 優先度 | スタック | ソース | 役割 | 同期 |
|---|---|---|---|---|---|
| alert | 5（最高） | 2KB | `Application/app_alert_task.c` | 転倒確定で**まず赤 LED を点灯**し、その後シリアルに通報と遅延を出力。回復で緑 LED に戻す | イベントフラグ `g_app_flg` 待ち |
| sysmon | 8 | 2KB | `Application/app_sysmon_task.c` | 周期ハンドラ（1 秒）で起床し、camera／ai／ui のハートビートが 5 秒止まったら警告。10 秒ごとに状態を出力 | 周期ハンドラ → `tk_wup_tsk` |
| camera | 10 | 8KB | `src/camera_display_thread_entry.c`（移植） | フレーム取得、AI 入力の前処理、取得時刻の記録 | VIN 割り込み → `g_ai_app_event` |
| judge | 11 | 4KB | `Application/app_judge_task.c` | 検出枠を受け取り `fall_judge` で判定。確定・回復を alert に通知 | メッセージバッファ `g_app_mbf` 受信 |
| ai | 12 | 32KB | `src/ai_inference_thread_entry.c`（移植） | Ethos-U55 で推論し、最大の検出枠と取得時刻をメッセージで送信（`TMO_POL`：判定が遅れても推論を止めない） | `g_ai_app_event` 待ち／メッセージバッファ送信 |
| ui | 14（最低） | 4KB | `Application/app_ui_task.c` | 200ms ごとに状態の色・文字と抽象化した枠を描画。**カメラ映像は描かない** | 周期起床、GLCDC の VSYNC 待ち |

- 優先度の方針：**通知（alert）を最優先**、監視（sysmon）を次に置き、処理の流れ（camera → judge → ai）の後に、見た目だけの UI を最低優先度にしました。推論や描画が重くなっても、転倒確定から LED 点灯までは遅れません。
- シリアル出力は複数タスクから呼ばれるため、**優先度継承ミューテックス**（`TA_INHERIT`）で排他しています（優先度逆転の防止）。
- 状態（判定結果・カウンタ）の共有は、書き込み側・読み出し側とも `tk_dis_dsp()`／`tk_ena_dsp()` の間で構造体をコピーし、途中の値を読まないようにしています。
- 設定値（優先度・スタック・判定しきい値・プライバシー UI の有効／無効）は `src/app_config.h` にまとめています。`APP_PRIVACY_UI_ENABLE` を 0 にすると、デバッグ用に元サンプルの画面（カメラ映像＋顔の枠）に戻せます。

### 遅延の計測

camera タスクがフレーム取得を完了した時刻（GPT タイマ、0.1ms 単位）を記録し、その画像の推論結果とともに judge へ渡します。転倒を確定させたフレームについて、alert タスクが **赤 LED を点灯した直後** に「フレーム取得 → LED 点灯」の時間を計算し、シリアルと LCD に表示します（確定待ちの 3 秒は含まず、別に表示）。

## 5. 転倒判定アルゴリズム（実装済み：`Application/fall_judge.c`）

姿勢推定モデルは変換・後処理のリスクが高いため、**物体検出の検出枠（BBox）＋時系列ルール**で判定します。OS に依存しない C のモジュールにしたので、PC 上で単体テストできます（`tests/`、13 項目）。

```
                   急な下降（1 秒以内に画面の高さの 20% 以上）
                   かつ 下 40% の領域に入る
  NORMAL ──────────────────────────────────────────────▶ SUSPICIOUS
    ▲   ◀──────── 上の領域に戻る（しゃがんで立った等）────────┘ │
    │                                                          │ 3 秒経過（見えなくなっても継続）
    │                                                          ▼
    └──────── 上の領域に 1 秒以上とどまる（起き上がり）────── FALLEN ──▶ alert タスク起床
```

- 位置は画面の高さに対する千分率で扱い、浮動小数点は使いません。32 bit のミリ秒カウンタの桁あふれにも対応しています。
- **現在のモデルは顔検出（YOLO-fastest）** のため、顔の枠の中心の「急な下降」と「低い位置での継続」で判定します。ゆっくり座る動作（1 秒あたりの下降が小さい）は転倒と判定しません。
- 人物検出モデルに置き換えた場合は `APP_FJ_USE_ASPECT=1` で、枠の縦横比（h/w < 0.8 で横たわり、> 1.2 で立位）も使います。
- しきい値（20% / 40% / 3 秒 / 1 秒）は `src/app_config.h` で変更でき、実機評価で調整します。

| 単体テストのシナリオ | 期待結果 |
|---|---|
| 立ったまま 10 秒 ／ 歩行（上下動あり） | 何も起きない |
| 3 秒かけてゆっくり座る | 転倒と判定しない |
| 素早くしゃがんで 1 秒後に立つ | 疑い → 取り消し、転倒なし |
| 0.5 秒で倒れてそのまま | 約 3 秒後に 1 回だけ転倒確定 |
| 倒れた後、顔が見えなくなる | 転倒確定は維持 |
| 転倒後に起き上がる | 1 秒後に回復 |
| 誰もいない | 何も起きない |
| タイマの桁あふれをまたぐ | 正しく転倒確定 |
| 人物モデル：横長の枠が続く／縦長に戻る | 転倒確定／回復 |

## 6. 評価計画（代替機到着後）

| 評価 | 方法 |
|---|---|
| 検知率・誤報率 | 立つ・歩く・しゃがむ・座る・転倒・起き上がるを各 10〜20 回。転倒動画をタブレットで再生してカメラで撮る方法で安全・再現性を確保 |
| 処理遅延 | alert タスクが出力する「フレーム取得 → LED 点灯」の時間を集計 |
| NPU の効果 | Ethos-U55 使用時と CPU のみの推論時間を比較 |
| 安定性 | sysmon の出力でタスクの停止がないことを長時間確認 |

参考値（公式サンプルを FreeRTOS で実機動作させたときの実測）: カメラ約 30fps、LCD 更新 約 35 回/秒、AI 推論 約 20 回/秒。
